# Durable local Paper ownership

Schema0019 adds immutable requested_paper_claims and nullable event ownership_token/ownership_accepted_us. The PostgreSQL library in core/paper/requested_ownership.py coordinates an explicitly controlled active requested-account simulation under the existing account row lock. It performs no exchange call or SQLite/PostgreSQL dual-write. Financial/control revisions and original financial/source export shapes remain unchanged; a claim does not reserve funds or advance either revision.

claim(engine,account_id,request_id,owner,ttl_seconds=30) creates a durable claim before any source event. Existing submitted/unowned histories cannot acquire retrospective ownership. Owners are bounded local coordination labels, not authenticated people. TTL is1..60 seconds; tokens start at1 and increase by1 on takeover, including when the label is reused. Unexpired same-owner retries return the original claim without extending expiry; another owner is rejected. Only expiry permits a new claim. There is no heartbeat, renewal, remote fencing guarantee or automatic scheduler. Database clock correctness is an operational prerequisite; observed backward clocks fail writes. Claims are immutable rather than an overwritten lease cache.

Once claimed, ordinary journal.accept and sources.accept reject that request; supported writes use deliver(engine,proposal,preview_sha256,owner,token). It validates current owner/token/expiry before work and again before commit. The original preview, dual versions, source receipt, funding/control admission and settlement are rechecked in the same account transaction. Event/source/settlement/fencing timestamp commit together; expiry while processing rolls back all effects. A token never grants funding/control permission. STOP still denies new submission but permits valid late fills for submitted requests. Independent zero-event finalization may close an owned request under the account lock; a lease never overrides closure.

Exact source retries require current unexpired ownership but return the original source acknowledgement, preserving the original event fencing token. Takeover never creates another SUBMIT or changes the original request/receipt. An expired closed-request owner cannot reacquire; existing evidence remains readable. Unknown results retain their full holds, and no ownership action authorizes remote retry or queries. Dispatch/transport and a uniquely durable external attempt contract remain incomplete.

GET /api/v1/paper-requested/ownership?account_id=ACCOUNT exports complete financial/control/source evidence, all immutable claims, event tokens and database-clock observation. Each request shows UNOWNED or LOCAL_LEASED, its latest claim and unexpired_at_observation separately from whether the request is active. This is a historical observation, not assurance of current validity. Existing local read-route access applies, not multiuser authorization. Separately granted default-disabled ownership and owned-source write routes are now documented in PAPER_REQUESTED_OWNERSHIP_API.md; main operator commands stay disabled. Next: uniquely durable local dispatch evidence before transport integration.

Offline: .venv/bin/python -m scripts.verify_requested_ownership FILE. Independent replay checks contiguous tokens, expiry-before-takeover, initial zero-event enrollment checkpoint, historical financial/control checkpoints, exact event order/token/time within the applicable lease and original source receipts. Missing/corrupt declared event fencing or claims blocks financial reads/writes without repair. Immutable triggers protect supported normal database operations; a privileged administrator disabling triggers can coherently replace/remove otherwise unobservable pre-event history. Hashes establish consistency, not signed origin, actor identity, freshness or authenticated completeness.

Original recovery-v1 is frozen and has no lease-history input: its ownership=NOT_IMPLEMENTED describes that version's unsupported ownership assessment. Use ownership-v1 export for actual lease evidence; do not infer claims from source labels or change original recovery calculations. Existing SQLite laboratory and older unowned journal events remain separate/unlabeled.

Claims are bounded to64 per request/100 requests, source events to1000 and complete export to32MiB. Capacity exhaustion rejects takeover without releasing reserves; read-only inspection remains available. Lock wait is2 seconds, not a whole-request deadline or throughput claim. Claimed evidence prevents destructive downgrade; empty migration roundtrip is supported. Nullable old events remain unowned. No new dependencies, credentials, domains, UI or services; no main fixture capital/trades/tokens. Restore with bash scripts/start.sh, preserve .env/volumes/proxy/CA and verify five services/current head0019. Live stays disabled.
