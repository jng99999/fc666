# Read-only readiness monitoring

Run `.venv/bin/python -m scripts.service_probe` from /workspace/fc666. It checks API dependency readiness, the frontend HTTP proxy, both public market symbols, research worker and Paper worker. Output is one bounded structured JSON record per sample; no remote body, configured URL or exception message is emitted. Any failed sample produces exit1, all passed samples exit0. Invalid command configuration exits2. These exit codes are suitable for a configured monitoring runner; the CLI does not itself install alert delivery or remain active after completion.

For a short development observation use `--samples 3 --interval 1`. At most120 samples and1..60 seconds between samples are accepted. For an actual deployment pass both `--api-url https://ACTUAL_API_ORIGIN --web-url https://ACTUAL_WEB_ORIGIN`; credentials/query/fragments/paths are rejected and HTTP is allowed only on loopback. Keep inherited network proxy and TLS verification. The probe never follows redirects or sends mutation requests. Each response has a16KiB decoded body cap and a5-second I/O timeout with elapsed-time checks while streaming. No exchange credentials are required.

Ready requires200 responses, explicit trading_enabled=false, true database/schema/Redis checks for API/web, healthy worker states and both BTCUSDT/ETHUSDT healthy for the market endpoint. One failing service cannot be hidden by healthy peers. A worker heartbeat and market status are limited readiness observations; they do not prove each account's integrity, successful queued research execution, sustained load or live financial correctness. `/system` separately checks real historical candles and a fresh WebSocket ticker snapshot; a subscription acknowledgement does not pass that check.

Executed evidence:17 unit cases cover individual failures, stale market coverage, false dependency health, unsafe trading flag, malformed/duplicate/oversize responses, redirect, transport failure and invalid origins. Three real current-instance samples passed; deliberately using the API origin as the web target returned404 on /api/health and exited1 with only web failed. No owned service was stopped for this injected misconfiguration. External monitoring service, notification destination, production deployment and long-running load acceptance remain unconfigured/unverified.
