# Paper 执行恢复检查契约

本切片为实时闭合柱 Paper 账户提供只读恢复检查。`GET /api/v1/paper/streams/{UUID}/recovery` 核对已持久化事实，帮助断线或进程重启后确认账户状态；它不接受恢复命令，不修复账本、不补成交、不提交订单，也不改变账户状态或版本。原有 `spot-paper-closed-close-v1` 公式、历史导出与人工控制契约保持有效。实盘关闭。

## 一致读取与证据

检查在单个 PostgreSQL `REPEATABLE READ` 事务中读取账户的冻结快照、全部已接受观察、持久账本、状态、版本及 feed，同时读取对应预热和已接受区间的当前公共柱、当前交易规则和 worker 心跳。服务器确定 `as_of`；心跳只采用不晚于该截止的记录，不使用未来心跳证明健康。worker 健康仍采用现有 10 秒窗口，不代表特定账户已经成功执行。

根据冻结输入重新执行原版本模拟引擎，完整账本必须与持久账本一致。所有模拟订单 ID 必须唯一，成交必须关联已存在的相同订单 ID，并保留原始决策、参考柱、观察时间、方向和模拟标志。ID 是由冻结快照和版本化订单语义确定的稳定标识，不是交易所订单 ID、外部确认或独立的人工控制请求 ID。

当前公共源仅用于核对已接受区间及规则是否仍一致，不把尚未接受的新柱拼入账本。发现缺柱、已接受柱修正或规则变化时报告 `NEEDS_REVIEW`，保留原账本和原始输入供核对；检查本身不将账户写成 `BLOCKED`，后续 worker 仍按既有消费契约处理。无法重构账本、格式损坏或订单/成交关系不一致时拒绝返回确认成功的检查结果，不能把损坏转换成零余额或健康状态。

## 状态与优先级

在账本核对成功后，源或规则不一致优先于以下生命周期结论：

| 条件 | 检查状态 | 含义 |
| --- | --- | --- |
| 任意生命周期，当前已接受数据或规则不一致 | `NEEDS_REVIEW` | 需要核对；没有自动修复或执行许可 |
| `RUNNING` / `PAUSED`，源完整，worker 健康 | `WAITING_FOR_BAR` | 已保存账本可复现；后续仍由原 worker 按账户状态及闭合柱规则消费 |
| `RUNNING` / `PAUSED`，源完整，worker 未确认健康 | `WORKER_UNCONFIRMED` | 账本可核对，但不能确认后续处理进程可用 |
| `STOPPED` / `LIMIT_REACHED`，源完整 | `TERMINAL_RETAINED` | 终止账户及资金、库存保留，不能恢复或自动平仓 |
| `BLOCKED`，源完整 | `BLOCKED_RETAINED` | 原阻断状态保留；当前源恢复一致也不解锁旧账户 |

`WAITING_FOR_BAR` 不保证源没有迟到或缺少下一柱，不保证下一柱能够成交，也不代表允许恢复 `PAUSED` 账户。页面同时展示原账户状态、feed、截止时间及 worker 证据，避免单一状态遮蔽这些区别。

账本中的待处理策略目标保持 `AWAIT_NEXT_CLOSED_BAR`，不是已提交订单。只有后续符合时序的闭合柱进入原消费事务后，才可能形成模拟订单；迟到、暂停、预激活和风险门禁继续适用。恢复不能为已经错过的柱补造过去成交。

## 丢失响应与重复执行

HTTP 响应丢失不能证明服务器未处理请求。用户应先读取账户、已有人工控制记录和本检查结果，核对服务器持久状态及稳定模拟订单、成交，再决定是否发起新的显式控制。检查与离线核对不自动重发 POST，也不把相同余额当作某次控制请求已经成功的证明。人工控制记录含请求版本及实际处理结果；它与模拟订单标识属于不同证据。

现有账户消费使用账户行锁，输入、账本、资金和版本在同一数据库事务中提交。重复扫描或进程重启复用已接受观察及确定性订单 ID，不另造同一已接受事实的成交。事务失败应回滚全部账户写入；响应在提交后丢失仍应通过读取核对。只读检查不能替代对这些性质的故障测试。

这一结论只覆盖本地事务模拟。未来真实交易所请求可能已经外部执行而本地没有确认，数据库事务和确定性模拟 ID 无法提供外部 exactly-once 保证。真实 OMS、幂等外部请求、交易所回执、私有成交对账与人工处置流程仍未实现。

## 完整导出与离线核对

导出保留本次一致读取的完整输入、原账户及账本、当前已接受区间的源数据和规则、所采用的心跳、服务器截止与检查结果。金额和时间保持原始精度，展示格式不得替换导出内容。离线验证重新构建原模拟账本、核对订单/成交关联和源差异，并重算检查状态；不读取当前数据库或网络，也不把今天的行情替换进旧检查。

验证文件上限为 32 MiB，未知版本、额外或缺失字段、未来证据、校验值不符及重算不一致必须拒绝。校验摘要用于内部一致性检查，任何人可以重算摘要；它不证明来源、观察时间、操作者身份或外部交易真实性。没有签名或外部存证。此检查导出与原 4 MiB Paper stream 导出为不同契约，旧验证工具继续支持旧文件。

## 故障验收与后续目标

本切片的验收覆盖隔离 PostgreSQL 中的只读性、一致读取、重复检查、各生命周期与 worker 超时、源缺失/修正/规则变化、损坏账本和无未来证据；离线导出必须复现同一检查结果。浏览器展示已确认检查时间，失败时不将旧结果冒充最新，断线重读不提交控制请求。

后续执行恢复验收需要逐项验证：并发 worker 扫描同一账户只提交一次；事务提交前失败无部分账本或控制记录；提交后丢失响应可通过持久记录核对；进程重启后保持已有订单 ID、成交和余额；迟到柱不补成交；公共数据修正与消费交错时不会静默改写已接受账本。测试使用隔离账户和数据库，不删除现有账户或数据卷。通过这些测试仍不意味着完成跨数据库灾难恢复、备份恢复、长时负载或实盘交易恢复。
