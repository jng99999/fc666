# Public market data quality evidence

`GET /api/v1/market/quality?symbol=BTCUSDT` (or ETHUSDT) returns a bounded, no-store `public-spot-data-quality-v1` report. It is a public read-only diagnostic, not an order command. Both healthy and unavailable reports return200; clients inspect status/reasons. Unsupported symbols return422. Existing market status now independently validates ticker/book envelopes, times and generation instead of accepting cache presence plus a book-valid flag. Existing readiness still depends on engineering dependencies, separately from public data health.

Live checks require exact supported instrument/symbol/channel identities, positive integer snapshot sequences, one matching bounded generation, healthy producer markers, decimal ticker fields, and ordered unique nonempty uncrossed top20 book levels with positive sizes and declared sequence metadata. Received and event times must be no older than15 seconds, and no more than2 seconds into the future relative to observation/receipt. Redis TTL alone is not treated as freshness. Producer book validity is a declaration from the existing delta-continuity worker; a top-level snapshot cannot independently reconstruct every missing delta.

Full quality additionally validates stored Binance Spot instrument identity and tick-price alignment, plus the latest three finalized one-minute bars. Bars must have valid aligned OHLCV, declared binance.public source, ascending contiguous exclusive intervals, close at/before observation, and newest close within75 seconds. This permits one normal minute interval plus15 seconds arrival grace. It does not scan older history or prove accepted corrections cannot occur. Stored rules have no authenticated refresh time; `instrument_rules_freshness_verified=false` remains explicit.

Rules and bars are read in one PostgreSQL read-only repeatable-read transaction with a2-second statement timeout. Autocommit is refused as storage unavailable. Ticker/book are read together with Redis MGET; acquisition errors, malformed/duplicate-key/oversized inputs and missing data fail closed. PostgreSQL and Redis are not one atomic checkpoint; `cross_store_atomic_capture=false`. Observation time is the local server clock after acquisition. Future-skew tolerance is a bound, not proof of exchange/server clock synchronization.

The report includes complete bounded evidence and a SHA-256 digest. `scripts.verify_market_quality FILE` recomputes all reasons/status/limits/flags, rejecting resealed false health or authorization claims and duplicate JSON keys; input/report bounds are256KiB. Each raw cache snapshot is bounded32KiB, rejecting nonfinite JSON constants before assembling evidence. Offline replay verifies quality at the recorded observation, not current freshness or authenticated origin. `read_only=true`, `submission_allowed=false` and `venue_origin_authenticated=false` are unconditional.

This slice does not add health policy enrollment, persisted request-linked health decisions, request-write/SUBMIT gates or health-triggered control changes. Existing immutable preparation/admission proofs retain their behavior. Next work must bind versioned health evidence to new preparation/submission without changing old receipts, and recheck acquisition at the write boundary. No fixture data is inserted into product market/account tables; no Live transport exists.
