# Selected trusted revocation checkpoint for recovery

`paper-operator-revocation-reference-v1` is a small read-only reference for the global retained revocation count/root/head. Capture audits the complete revocation chain and checkpoint under the shared database fence. It does not contain plaintext credentials, alter grants or repair financial/authorization state. The reference is bounded at4KiB and1024 revisions, with exact version/scope/flags/hash validation.

Capture on the intended trusted source: `.venv/bin/python -m scripts.operator_revocation_checkpoint capture --output /protected/new-reference.json`. Output is exclusive/new-only mode0600, refuses a final symlink and fsyncs file contents. Securely preserve the selected reference independently of the database being restored. Directory durability, signatures, independent storage and automatic trusted-reference distribution are not supplied. Capturing into the same cloud workspace is a local smoke check, not independent offsite acceptance.

Compare a restored/configured database: `.venv/bin/python -m scripts.operator_revocation_checkpoint check --expected /protected/trusted-reference.json`. The tool first fully audits database records/checkpoint, then requires exact selected revision/root/head/envelope equality. Earlier or later checkpoints both differ from the selected reference. Successful output identifies the selected checkpoint hash, sets matches_selected_checkpoint=true and currentness_independently_verified=false; external_submission_allowed remains false. Matching does not authenticate the file, database identity or independent currentness. Empty checkpoints are identical across empty stores, so origin/trust must remain external. A stale selected reference can match a stale backup; the operator must supply the intended authenticated current reference and quiesce/coordinate recovery appropriately.

Bounded input rejects duplicate JSON keys, nonfinite constants, unsupported fields, invalid hashes/revisions and oversized raw files. Symlink and non-regular input, including a FIFO without a writer, fail instead of blocking. Errors do not dump file contents, credentials or database exceptions. No import, rollback, state promotion or live-trading authorization is implemented.

The existing restore drill accepts `--expected-revocation-checkpoint /protected/trusted-reference.json`: `.venv/bin/python -m scripts.backup_drill --directory /protected/drill --expected-revocation-checkpoint /protected/trusted-reference.json`. Programmatic callers can supply expected_revocation_checkpoint. Validation occurs before backup target/directory setup. The restored database must pass the existing whole-schema/table-count/content-hash verification and selected checkpoint check before success is recorded. Mismatch fails and cleanup removes only the generated isolated target; no success manifest is published. These checkpoint comparisons are read-only.

Opted-in reports use fc666-local-backup-drill-v2 and record the selected checkpoint verification/hash. Default drills retain fc666-local-backup-drill-v1 semantics and existing additional-verification callbacks. Neither report claims independent currentness or offsite retention. Full records and the singleton checkpoint remain covered by the database backup; the small reference is not a replacement backup.

Tests use isolated source/restored databases and artificial tokens. A genuine custom backup is restored, the isolated source advances, and the restored older complete coherent state is rejected against the newer selected reference. It still matches its older selected reference, explicitly demonstrating why reference trust/currentness cannot be inferred. Tests also cover mismatch cleanup and protected file/CLI behavior. No main database revoke or fixture write is used to demonstrate this feature.

Schema0030 and existing startup/configuration/dependencies remain unchanged. No API restart, frontend build, new credential, domain or service is needed. Actual independent-storage/trusted-reference deployment and recovery freshness acceptance remain pending, together with identity/allow grants, scheduling, risk and public release.
