# 官方新闻与真实行情模拟验收

在唯一主源码增量接入，实盘固定关闭；不注册付费服务、不新增依赖、不修改旧账户新闻来源或账本。

## 来源与风险政策

- BLS 官方 `https://www.bls.gov/schedule/news_release/bls.ics` 与当前月日历：US-Eastern，按 America/New_York 和夏令时转换。BLS明确提供自动日历订阅并允许使用公开内容。本机普通HTTP为200，账户服务器为Akamai通用403，拒绝原因未确定；不改请求身份、不解挑战、不轮换节点。由本项目固定Vercel节点正常订阅两个固定官方资源，是否可用必须以该节点真实响应验证。固定 `/api/public-calendar/bls` 无客户端目标参数、只读、最多60秒缓存；保留实际获取时间、上游Date/Last-Modified、内容摘要及原文，失败503，不给旧资源续期。账户服务器需明确配置此订阅节点，仍校验原始取时及每个必要来源的过期。
- BEA 官方 `https://www.bea.gov/news/schedule/ics/online-calendar-subscription.ics`：UTC 日历。
- Federal Reserve 官方 `https://www.federalreserve.gov/json/calendar.json`：官方事件列表。其 JSON 未附时区，有具体时刻的条目采用 America/New_York 的发布惯例；这是明确的解释假设，不冒充上游显式时区。缺失或近似时间按整日不确定风险截断许可覆盖，不伪造零点发布时间。
- Bitget 官方 `GET /api/v2/public/annoucements`：只用结构化 `security`、`maintenance_system_updates`、`symbol_delisting` 类别；分页完成3小时已发布公告回查。按原始 cTime 触发已发布公告冷却，保守作用于所有监测加密产品，不靠标题关键词猜影响或币种。

宏观事件统一按 HIGH 处理，是本平台保守禁入政策；Bitget上述风险类别同样按 HIGH。宏观计划适用于黄金和加密，Bitget公告不作用于黄金。所有来源必须成功验证才发布新许可；不完整分页、无法解析、超时、限频、空损坏内容、持久化失败均禁止新风险。

FRED网页曾作为备用来源研究，后因其使用条款不适合本平台而排除，未接入自动采集或部署；不把公开200当成使用授权。ForexFactory与需申请的Bitget RSS同样未作为默认源。

本源只监测列举的美国宏观计划与已发布Bitget风险公告。未来覆盖指已经列出的官方宏观计划，不代表预知未来交易所公告，也不是全世界新闻、战争、黑客事件或所有交易所的完整监测。计划仍可能被发布方调整。初次观测之前没有历史新闻覆盖资格，不把今日采集时间伪造成历史 known_at。

## 与原执行链路连接

独立线程采集，报价与已有止盈止损不等待新闻网络请求。观测时间只随成功的实际采集或验证推进，读取缓存、刷新网页和重启不能续期。原始时间、上游Date/Last-Modified、内容摘要及许可边界作为独立证据保存；原金融表不变。

源标识 `official-us-calendar-bitget-v1`；原生快照 `GET /api/v1/directional/news`，诊断 `GET /api/v1/directional/news/status`。网页代理均仅允许GET。启动需要明确设置 `DIRECTIONAL_PUBLIC_NEWS_URL`；管理员保存的新闻 source/url 必须与内置源及该URL精确匹配，才直接读取本机缓存。自定义HTTP新闻路径保留，失败不自动回退内置源。

测试站连接地址为 `https://fc666-test.vercel.app/api/directional/news`。只更新加密配置库的news字段，保留模型、黄金、账号授权及所有秘密；记录版本及可逆备份。原账户来源已冻结，必须新建本次验收账户，不改写旧配置。管理员仍可在站内更换来源。

## 完成条件和证据分级

1. 官方接口实际联网成功，保存原始结构与安全响应头；不通过登录、验证码或反爬限制。
2. 解析、时区、重复、未知时刻、分页、过期、断网、持久化和并发失败通过对应测试；新闻不可用时仍执行已有保护。
3. 同一提交完成构建、完整CI及服务器Python3.12隔离服务验收，再更新测试站。
4. 新建独立真实行情模拟账户，按实际自然信号记录开仓、费用、止盈止损、消息禁入。不能为了出现多空或某个退出结果而修改行情、新闻、时钟、已冻结策略或人工下单冒充自动策略。
5. 没有自然发生的方向、保护退出或实际高影响窗口，明确列为尚未观察到；真实历史回放与合成测试另行标记，不充作实时成交。黄金必须等实际有效报价及闭合采样，不补造历史。
6. 只停止本次自建验收账户，保留完整账本；核对原账户不可变记录未变。页面显示当前源、采集状态、覆盖、近期事件及原始来源，手机可读可操作。

## 真实前向发现的历史到达问题

2026-11-15 22:57 UTC 对 Bitget 连续8次真实抓取发现：最新1m柱在时间闭合29秒后仍改写high/close及volume，其余499柱稳定。仅以时间闭合认定可用，会在下一分钟重复发现旧柱变化，触发隔离及等待新柱，影响规则执行。不能删除真实修订校验来强行成交。

新增明确的 `DIRECTIONAL_BITGET_SETTLEMENT_SECONDS=60` 部署策略：在服务器和上游时钟较早者减去等待秒数后，按周期确定可接收历史边界；请求、缓存跳过与输入校验共用该边界。黄金是本地真实采样，等待为0。60秒是本平台的最低到达等待，不保证上游终版；更晚的真实修订仍隔离。

账户冻结等待秒数与 `minimum-arrival-wait-v2`。旧账户不得静默换采集方式；版本不匹配禁止新规则开仓，旧账本及止盈止损保留，需要新建账户。默认0仅兼容旧部署与明确的旧版实验，不是生产v2配置。

先完成3df72ab版本的固定20分钟前向记录，再以新提交、新隔离数据开展v2前向；两个结果不可混报。已有120组历史回测是无实时到达延迟的OHLC成交模型，没有验证这个新到达策略的收益；同样指标规则不代表相同可用数据时间，不能直接声称历史收益适用于v2实时执行。
