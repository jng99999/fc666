# Paper 逐单事前规则授权与账户门禁验收

每个新准备批次在第一事务中保存完整新预计订单的规则授权，包括原订单、预计数量/价格/费用和预计成交后账面值、ALLOW_SIMULATION/DENY_SIMULATION及原拒绝原因。预计值不进入真实Paper账本。账户方向门禁冻结生命周期和风险停止状态，禁止买入时仍保留原规则允许的卖出；批次内金额/容量/风险变化由原计算继续逐笔处理。

消费前重算并精确比较全部授权；接受后再次核对实际新增订单与成交等于原预计值，再与账本和CONSUMED同事务提交。授权缺失、多余、载荷冲突或版本未知均失败回滚。准备授权标记NULL的历史批次不追认：待消费批次取消AUTHORIZATION_MISSING；旧终态检查显示LEGACY_UNAVAILABLE。数据库阻止授权修改、删除以及准备授权标记的后改。

审阅补上授权保存时间不得晚于批次结束的检查。只读检查还核对CONSUMED的实际接受观察和原模拟回执，不能只凭结束标记宣称消费发生。最新20批次完整核对，total_batches/window_limit/has_older明确更早历史不在窗口，不删历史或截断单批授权；这样避免1000条准备的平方级历史重算。响应最多32 MiB，不提供独立离线授权复算或历史分页。

测试覆盖预计价/数量/费用与实际匹配、部分成交、风险拒绝、暂停、halt买拒卖可、多柱拒绝、缺失/额外/冲突授权、未知版本、真实旧NULL准备取消、不可变触发器、两次提交回滚、并发/提交后丢确认、后来控制与行情下历史计划复算、只读API、大小限制、授权晚于结束、虚假CONSUMED和20批范围。全部使用隔离DB；产品不制造行情、成交或旧授权。

全套364项测试通过（101.67秒，1项既有FastAPI/httpx弃用警告），其中23项新增授权专项全部执行；迁移完整base/head往返与Alembic检查通过。前端初次类型检查发现新增schema括号错误，拆分payload/batch/schema定义修复后，TypeScript和生产构建通过。五服务恢复后，真实已停止且有旧模拟成交账户浏览器验收通过：停止账户买卖门禁均关闭、最新20批范围明确、失败清除旧授权确认、轮询组件唯一、393px无溢出/JS错误、账户不变；原恢复与独立完成态意图导出离线核验通过。真实旧账户不追认历史授权；非空预计订单及消费效果由隔离数据库/API专项验证。迁移0012，无依赖/秘密/网络域名/服务新增；五服务启动入口不变。下一目标是独立订单生命周期与回报对账的Paper验收，实盘OMS、账户身份权限、共享资金、私有交易所接口、外部exactly-once与Live仍未实现。
