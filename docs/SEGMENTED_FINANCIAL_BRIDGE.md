# Atomic frozen-ledger segment bridge

`core.paper.requested_segmented_bridge.apply` is a trusted internal library primitive for legacy unmanaged local Paper accounts. It applies at most16 new events from one independently verified complete segmented-account candidate to an already prepared request, using one PostgreSQL account lock and transaction. It does not create accounts/requests, increase frozen1000-event account capacity, introduce a new database financial version, expose an HTTP endpoint or supply authentication. Controlled and pool accounts are rejected; their source/owner/dispatch/health/pool integration remains a separate gate.

Callers provide the exact prior financial revision and SHA256 of the complete account projection from `requested_segmented_account.capture`. The candidate must add exactly one final source segment to that checkpoint; all financial history, request base, summary and immutable events are replayed. Each event runs existing `_accept` checks and audits inside the same transaction. Final account/active request/clock/revision/counts must match the proposed replay or the entire transaction rolls back. Partial independent delivery makes the checkpoint stale rather than resuming an incomplete proposed batch silently.

Exact retries acknowledge only candidate events that already exist as an identical immutable prefix. This works after later settlement and does not reapply fills, change balances or release later holds. The predecessor proof is still required for retries. An independently valid hash is internal consistency, not approval or authenticated venue origin. Returned candidate flags describe the offline artifact's absence of authority; financial persistence occurs only through this explicit internal transaction. No persisted segment-format receipt or authenticated command acknowledgement is introduced.

Scope remains a development prerequisite. Controlled source receipts, worker fencing, complete shared-pool transaction binding, new-version financial persistence beyond the frozen limit and automated scheduling are not provided by this bridge. Do not wire it into public operator routes or workers without those separate authority contracts. Keep grants absent, Live disabled and main financial tables unseeded. Tests use isolated databases.
