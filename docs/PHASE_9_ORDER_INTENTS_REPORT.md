# Paper 独立完成态订单意图验收

本切片将实时闭合柱模拟引擎已产生的原订单与成交，保存为独立不可变记录；不改变原模拟价格、容量、费用、策略与风控计算。账户命名空间摘要避免不同账户共享原订单 ID 时混淆，保留 FILLED、PARTIAL_CANCELLED 和 REJECTED。状态路径数组与终态在同一事务保存，不声称存在独立提交的执行前队列。

迁移0010添加可空账户版本标记与 paper_order_intents。旧账户在只读检查中明确为 LEGACY_UNMATERIALIZED，GET 不补写；下一次原有授权控制或 worker 消费先核对并原子物化历史回执。原始资金和回执不重放，实际保存时间和历史观察时间分开。已经声明完整覆盖的账户若缺记录、载荷不符或版本不支持则拒绝，不能自动修复。

并行契约审阅发现旧标记与已有独立记录冲突时写入路径原本会接受，已修为与读取一致的拒绝处理。数据库触发器阻止 UPDATE/DELETE；同账户行锁与唯一约束阻止重复经济事实。读事务使用 REPEATABLE READ；完整冻结输入、状态路径、原回执与截止导出供离线核验，32 MiB 上限不截断。

专项18测试通过：三种终态、完整载荷、账户隔离、并发同柱去重、提交前已flush的回滚、不可变数据库触发器、旧账户零写入读取、物化和物化回滚、缺失覆盖拒绝修复、API 200/404/405、离线篡改/未来证据/未知版本/孤立记录/大小上限。原闭合柱和丢确认/连接重建故障26测试亦通过；迁移完整降级至base并升级、原恢复检查12测试通过。

全套318测试通过（120.74秒，1项既有FastAPI/httpx弃用警告），Alembic检查无新操作，TypeScript与生产构建通过。五服务恢复后，真实已停止且有模拟成交账户的浏览器验收通过：旧账户明确未物化、两种检查导出离线复算、读取零账户变更、409失败清除旧确认、刷新和393px页面无溢出或JS错误。当前真实旧停止账户意图导出为 LEGACY_UNMATERIALIZED（0独立行、1原订单），没有为了演示而补写或重放成交；VERIFIED与三种终态由隔离PostgreSQL/API专项测试验证。启动保持五服务、既有.env、数据卷、proxy/CA，不增加依赖、秘密或网络目标。下一目标是执行前单独提交并恢复的待执行意图与消费状态机。实盘 OMS、UNKNOWN_SUBMISSION、交易所对账、多用户鉴权、共享资金和外部 exactly-once 仍未实现。
