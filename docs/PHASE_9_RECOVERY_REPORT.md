# Paper read-only recovery and fault acceptance

User-authorized parallel tasks delivered an independent recovery contract review and four database fault tests; the parent integrated a repeatable-read recovery inspector, stable simulated order/fill receipts, UI and full offline verifier. Contract: PAPER_RECOVERY.md. Existing simulator formulas, accounts, order IDs and controls remain unchanged. This is the first Goal5 inspection slice, not a durable independent intent/OMS or exchange execution implementation.

Eleven inspector tests cover complete ledger reconstruction, exact retained order/fill identity, no account writes/replay, changed/missing accepted source or rules becoming NEEDS_REVIEW, five lifecycle states with worker evidence, future-input rejection, complete-output bound, malformed account rejection and read-only API/missing accounts. Four additional fault tests inject acknowledgement loss after a successful commit, dispose/rebuild database connections with both buy and sell history, raise after SQL flush but before commit to verify complete rollback, and run twelve concurrent retries after connection disposal. Economic state and stable receipts remain exact; polling feed may legitimately change from CURRENT to WAITING without another trade.

Full suite: 300 passing tests. Acceptance covers migration consistency, TypeScript and production build, owned-service restart/readiness, real-browser inspection of an existing stopped account containing a genuine simulated fill, exact downloaded export/offline reproduction, unchanged account, failure-clearing behavior and 393px layout/no JavaScript errors. Test fixtures are isolated PostgreSQL data; no fake market values are inserted into product storage. The browser does not create or modify accounts or receipts. A duplicate sibling React-key issue found during polling acceptance was fixed for realtime recovery and portfolio history widgets; tests now verify a single inspection after repeated polling and single independent widgets after scenario switching.

Capture uses a single REPEATABLE READ snapshot of account, original accepted-source interval, current rules and heartbeat no later than server as_of. Current new bars are excluded from the ledger. Source/rules mismatches are reported without blocking or repairing the account; corrupted ledger is rejected. PAUSED retains pause, stopped/limit accounts retain inventory, BLOCKED is never unlocked. WAITING_FOR_BAR is not authorization or a promise of execution. Pending strategy targets remain unsubmitted decisions. Receipts are simulator identifiers, not exchange acknowledgements.

No migration/dependency/credential/host/service changes; schema0009, five owned services, Live disabled.
