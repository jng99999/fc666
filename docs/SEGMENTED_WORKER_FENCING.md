# Trusted local worker fencing for the independent ledger

`paper-segmented-local-worker-v1` is an opt-in internal PostgreSQL worker lease contract. It does not authenticate an operator, prove market/source provenance, grant scheduler/venue authority or connect the application worker to this ledger. Live remains disabled. Existing unbound segmented ledgers retain their financial contract and can never enroll retrospectively after any financial command.

Schema0028 adds an irreversible `worker_version` marker on the financial ledger and immutable `segmented_paper_worker_records`. Explicit enrollment binds only the root (commit0). Missing an entire record chain cannot silently return the ledger to unmanaged writes. Ledger reads, retries, capture and new commands audit both financial evidence and the declared worker chain. Triggers forbid worker record update/deletion and marker removal; populated downgrade refuses to discard a marker or record.

The trusted internal functions are `segmented_worker.enroll`, `claim` and `execute`. Claim requires the exact current financial node hash, predecessor token, stable command ID, bounded owner ID and explicit1..60-second duration. PostgreSQL clock supplies acquisition and expiry; takeover requires previous expiry and increments the token, at most64 claims per ledger. A claim retry must match original identity/checkpoint/duration and remain the current unexpired claim. There is no lease renewal, implicit extension, token reuse or reset. Caller-supplied owner strings are trusted internal identities, not authentication.

Once bound, ordinary `segmented_ledger.execute` refuses even historical retries. The worker entry requires the current owner/token/unexpired lease before replay, and checks expiry again after settlement before adding an immutable ACCEPT receipt. Financial commit/cache and its receipt commit in the same account lock/transaction. Failure or expiry during replay rolls back all three. ACCEPT binds original command ID, exact financial node, current claim token/owner and database acceptance time. The entire chain must cover every non-root financial commit exactly once. Acceptance time is checked before transaction commit; this does not guarantee the commit finishes before lease expiry.

Original financial command retries produce their original financial view after auditing current evidence and checking the current lease, without creating another receipt or modifying a later hold. A successor owner may acknowledge a prior command only while holding its own current lease; an expired or fenced predecessor cannot. Financial/current claim queries use2-second account lock timeout. Same-account concurrent contenders serialize; conflicting active claims/checkpoints and conflicting financial retries fail.

Worker evidence is bounded at576 records of at most16KiB each (one enrollment, up to64 claims and up to511 financial admissions). Financial account/event/commit/storage caps remain unchanged. No automatic pruning, assured terminal capacity, pool/source/control/health gates, STOP/late-fill scheduler, public worker endpoint or complete operator authorization is supplied. Financial archive v1 exports only financial commits: capture audits binding evidence in the database, but its offline verifier does not export or verify worker claims. Complete financial-plus-local-worker operational export/offline replay is now available under a distinct version; see SEGMENTED_OPERATIONAL_ARCHIVE.md. Operator/source/control/health/pool evidence remains outside that scope. `operator_worker_binding_supported=false` therefore remains correct for the complete application integration.

Recovery uses the existing checkout/configuration/volumes. Stop only owned API, then run `bash scripts/start.sh` to migrate0028 and restart API; check all five services and `.venv/bin/alembic check`. No frontend rebuild, new dependency, credential, domain or main-ledger fixture is needed. Tests enroll only isolated database fixtures.

Scoped single-operator HTTP evidence access and explicit root enrollment are described in SEGMENTED_OPERATOR_ACCESS.md. Enrollment now supports an optional explicit root checkpoint for authenticated callers. No HTTP claim or financial command is enabled; complete application integration remains false.
