# Unified five-block delivery

One authorized execution programme replaces requests to confirm each small slice. Existing checkout and financial evidence are preserved. Install/test/fix/commit/push within this programme are authorized. Live remains blocked by actual incomplete execution/reconciliation/identity and acceptance requirements; a health endpoint or local test never establishes production readiness.

| Block | Local acceptance targets | Remaining full-delivery gate |
| --- | --- | --- |
| OMS | Durable bounded staged-unapplied input, strict identity/retry/fences, retained funds, crash recovery | Segmented journal application, scheduler integration, archive restore and complete order lifecycle |
| Portfolio/risk | Audited multi-account requested holdings/holds and aggregate stress/exposure in one DB snapshot | Shared inventory/transfers, portfolio execution policies and enforcement across scheduler |
| Private identity/connectors | Read-only fixed-host signed Spot query client, bounded response parsing and sensitive-error redaction | Secure credential provisioning, real authenticated account/order/fill snapshots, reconciliation, identity isolation |
| Production | Repeatable backup/restore drill, dependency/engineering monitoring, CI acceptance and rollback instructions | Actual target infrastructure, independent backup retention/restore, sustained load, infrastructure failures and deployment |
| Research | Bounded chronological walk-forward grid selection with causal training-only selection and replay | Job/UI integration, full SDK sandbox, matching/data coverage and reproducible AI programme |

These targets extend existing real features; they do not substitute foundations for complete production blocks. Deliver the executable local targets, then continue remaining code/integration work. Track test evidence separately from externally blocked acceptance. Actual environment configuration currently has no private exchange credentials or production target. Values must be provisioned securely in supported settings, never in chat or tracked files. No estimated percentage/date is asserted without a validated scope and throughput baseline.
