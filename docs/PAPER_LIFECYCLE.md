# Paper 独立订单生命周期与回报核对契约

本切片在已有两阶段准备、逐笔规则授权和独立模拟终态之外，增加不可变的本地生命周期事件。CREATE 在独立准备事务中保存，FILL 与 OUTCOME 随实际消费结果原子提交；取消准备则保存对应的 CANCELLED 结果。它们描述本地 Paper 事实，不是交易所请求、ACK、私有成交或取消确认。原 `spot-paper-closed-close-v1` 引擎、稳定订单 ID、数量、费用、风险拒绝和账户控制语义保持有效；Live 继续关闭。

## 覆盖、身份与执行前创建

准备关联独立不可变覆盖行，版本为 `paper-local-lifecycle-v1`，保存实际登记时刻与 `NEW_PREPARATION` 或 `LEGACY_PENDING_ENROLLMENT` 来源。事件关联账户、准备、逐笔授权和原模拟订单身份；事件 ID 与序号必须确定、稳定，并参与完整内容核对。CREATE 与准备及授权在第一阶段事务中共同提交，不能先接受本批 observations、成交、现金或库存变化。提交后响应丢失，重试读取同一创建事实；不能创建第二组事件或通过忽略唯一冲突接受不同内容。

CREATE 保存原决策、方向与获授权的预计数量上限。该上限来自冻结候选成交投影，不表示原策略最初想下的完整数量。特别是原引擎 `PARTIAL_CANCELLED` 的未成交原始需求未作为独立字段保留，不能从成交量反推它、补造完整 requested quantity，或据此声称已支持外部订单剩余量管理。拒绝授权没有预计成交，不能虚构正的获授权数量。

策略 pending target 仍不是独立订单。没有新增原订单的准备可以保存零事件，但只有当前版本覆盖且完整重算确认为零，才可以报告核验通过。

## 消费、取消与原子性

消费沿用账户先于准备的锁顺序。冻结 base、控制、规则、行情、时限、完整逐笔授权及已经独立提交的 CREATE 均通过核对后，才接受原引擎产生的效果。实际接受的模拟成交与冻结授权投影完整逐项比较成功后，才用已经证明相等的投影保存 FILL 和最终 receipt；仅有投影或 CREATE 不证明成交。两者不同须回滚，不能以先前预计成交直接冒充已成交。

FILL、OUTCOME、原账本、余额、独立订单意图及 CONSUMED 准备在同一个消费事务中提交。原结果为 FILLED 或 PARTIAL_CANCELLED 时保留精确终态与实际回执；REJECTED 没有 FILL，OUTCOME 保存原拒绝原因。若准备因控制变化、过期或行情变化取消，对已创建的本地订单保存 CANCELLED OUTCOME，原 CREATE 和逐笔授权保持不变，且不产生本批经济效果。这种准备取消不是交易所撤单确认。

准备取消结果与准备 CANCELLED 状态必须同事务提交。所有写入任一步骤失败均完整回滚；重复或并发消费、取消，以及提交后丢响应，不能追加第二次成交或冲突终态。事件不可更新或删除，数据库约束与应用完整内容比较共同防止覆盖。

## 纯归约与回报一致性

纯归约器按序号排序，按完整稳定事件 ID 去重；同 ID 同内容的重复投递可幂等归约，同 ID 不同内容、不同 ID 占用同序号、序号缺口或非法状态顺序均拒绝。事件时间不代替序号，读取顺序也不成为业务顺序。

生命周期始于 CREATE，允许相应的实际 FILL，最终由唯一 OUTCOME 结束。不得终态回退、终态后追加成交、跳过 CREATE 或将取消改为成交。每笔成交数量必须为正，累计成交数量不得超过 CREATE 冻结的获授权预计上限。归约使用精确十进制运算，累计数量、费用和名义金额必须与原最终模拟回执逐项一致；订单关联、方向、决策、执行和观察时刻也必须完整核对。不能只核对订单 ID、事件摘要或最终状态字符串。

当前持久契约仅接受 CREATE 序号0、可选单笔 FILL 序号1及 OUTCOME 序号1或2的精确标准路径；数据库也将序号限制为0至2，完整覆盖检查将所有内容与授权及准备结果逐项比较。纯归约器可使用隔离夹具验证多个分量成交的累计规则，但此能力不是当前数据库或生产消费路径的多回报支持。当前原引擎以一个本地成交回执结束订单。归约器的累计规则不意味着已接入外部增量成交、外部累计数量更新或异步回报队列。FILLED、PARTIAL_CANCELLED、REJECTED 必须保留原引擎含义，不能统一为成功。完整性的冲突、遗漏、未知版本或超限必须失败，不得作为普通取消理由掩盖。

## 历史兼容

没有生命周期版本覆盖的历史准备显式显示 `LEGACY_UNAVAILABLE`。历史 CONSUMED 或 CANCELLED 不补造过去曾经独立持久的 CREATE、FILL 或 OUTCOME；GET、浏览器打开和检查均不写入历史事件。

部署前尚为 PREPARED、且具有可验证当前逐笔授权的旧准备，可以在独立准备事务中登记本地 CREATE，并标记来源 `LEGACY_PENDING_ENROLLMENT`。登记保存实际时刻，不追认过去存在创建事实；消费必须发生在该独立事务提交之后，并重新核对全部既有门禁。缺少可支持授权的旧准备仍按已有授权兼容规则取消，不能临时补授权获得执行资格。

已经具有生命周期版本覆盖但应存在的事件缺失或冲突属于损坏，不能降级为历史不可用或自动补齐。历史登记也不得追补终态订单，改写原账本或消除原有时限、来源和控制检查。

## 只读窗口与验收边界

只读检查在一致的数据库快照中读取并核对最新 20 个准备批次，返回 total_batches、window_limit=20 与 has_older。每个选中批次的事件必须完整核对，不能截断逐笔事件后声称完整；更早批次不在本次核验范围。版本覆盖与 `LEGACY_UNAVAILABLE` 分别显示，读取失败清除旧确认。页面不得提供重放、修改回报、补成交或取消订单的执行入口。

本阶段重点验收独立 CREATE 提交、消费中途回滚、实际回报与投影分离、重复和乱序投递、冲突身份与序号、累计数量上限、精确费用与名义金额、准备取消原子性、提交后丢响应、连接重建及并发重复消费。故障范围按实际测试说明，连接重建不能替代完整进程或基础设施重启验收。

终态之后迟到的成交或其他事件会报“需要独立对账”的完整性错误，当前没有自动修复或吸收这些事件的路径，不能声称已处理真实交易所成交与撤单竞态。

完整 OMS、私有成交与取消竞态、未知外部提交状态、外部累计回报更新、真实交易所幂等请求、共享资金风控及身份权限仍须后续设计与验证。本切片不能证明外部 exactly-once、交易所真实性或历史事件时间的外部真实性。
