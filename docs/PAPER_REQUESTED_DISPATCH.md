# Unique local Paper submission evidence

Schema0020 adds immutable requested_paper_dispatches and nullable event dispatch_version. A new owned local SUBMIT automatically declares paper-requested-local-dispatch-v1 and commits one request-scoped dispatch record with its event, source receipt, SUBMIT gate, fencing timestamp and account update. The original DELIVER_OWNED_EVENT grant and current owner/token/expiry, financial/control preview and risk/funding checks still apply. This supplementary evidence creates no additional financial/control revision or reservation. No new write route/grant exists.

The immutable record binds the frozen request hash, stable local client_id, original SUBMIT hash, source-receipt hash, original owner/token, complete original claim hash and the event's database acceptance clock. client_id is a hash of version and request identity; it is not an exchange client-order ID or assertion of external delivery. A primary key permits one dispatch per request and a unique client_id prevents local identity collisions. A composite foreign key retains the original ownership claim. Immutable triggers protect both record and event declaration.

Exact retries return the original source acknowledgement and retain the original dispatch, including after takeover, later fills, sealing and another active request. A new owner cannot create a second SUBMIT/attempt. Missing or corrupt declared evidence blocks all journal/source/ownership/recovery reads and further writes without repair. An exception or process death before commit leaves no partial event/receipt/gate/dispatch/cache; lost response after commit reopens to exactly one original record. Lease expiry during processing continues to roll back the whole transaction.

Old owned/unowned events remain dispatch_version=NULL with no fabricated record. Retries do not retrospectively invent dispatch identity. Their recovery explicitly reports DISPATCH_PROVENANCE_UNAVAILABLE; old source declarations and financial/source/ownership/recovery-v1 formats remain unchanged. Only the new complete dispatch export assesses this extra evidence. Privileged administrators disabling triggers can coherently replace history; hashes and immutable normal-operation guards are not authenticated completeness or administrator-proof provenance.

GET /api/v1/paper-requested/dispatches?account_id=ACCOUNT captures a complete locked ownership/source/financial/control snapshot, one dispatch coverage slot per request and derived recovery assessments. Existing local read access applies, not multiuser authorization. Offline: .venv/bin/python -m scripts.verify_requested_dispatch FILE. Independent reconstruction compares every record to its original source receipt, SUBMIT event, owner claim and fencing time. Unsupported versions, incomplete/resealed inconsistent histories and duplicate JSON keys fail without partial output.

Recovery reports NOT_DISPATCHED_LOCAL for no local event, LOCAL_VOIDED for zero-event finalization, WAIT_LOCAL_RESULT for declared SUBMIT/UNKNOWN_SUBMISSION, RECONCILE_LOCAL_PREFIX for known nonsealed receipts/fills and LOCAL_SEALED for explicit local sealing. Every result has resubmission_allowed=false and external_query_supported=false. Local absence never establishes remote absence; local SEAL is not venue finality. Unknown results retain full holds and cancellation acknowledgement retains unfilled holds until SEAL. Current balances/active request remain in the complete nested journal, separate from each historical request's funding summary.
