# 三规则回测与模拟执行验收目标

固定主源码原位增量，实盘始终关闭。协议先固定为 `closed-rules-backtest-protocol.json`，再读取结果；不因亏损改参数或选择有利时间段。

1. **同规则可复现**：结构/FVG、固定箱体、趋势回撤复用线上规则版本与滚动 500 柱语义；原始数据、新闻、费用、代码摘要可核对。相同输入重跑得到相同结果，保存失败与零交易。
2. **真实历史与成本对比**：BTC/ETH 各 1h/4h、每组 2000 根闭合柱；完整区间与固定后 40% 区间，分别以独立资金启动。比较基准与压力成本下的净收益、回撤、多空成交、止损止盈、累计费用和剩余持仓。跨产品数量不同，禁止直接混排为统一资金组合。
3. **黄金单列验证**：尝试固定 2025-01 原始公开配对 tick，按时间取首尾各 2000 个合格 1m 样本，不按收益挑选。若下载不可用则如实标记缺口；不能用现有 1h/4h 替代。HistData 与实时 Swissquote 的来源和采样密度不同，结果仅为来源外诊断。
4. **真实执行边界**：收盘决策、下一柱开盘模型成交；不在同一已知收盘回填，缺口不补造成交；同柱止盈止损都可能触发时保守选择止损。原始 OHLC 不代表真实历史 bid/ask/盘口，显式点差与滑点假设必须显示。
5. **消息门禁可测**：默认 `REQUIRE_HISTORICAL`，无真实历史新闻时必须零开仓。`UNCOVERED_RESEARCH` 仅用于明确标记的离线成本诊断，永不产生实盘或线上自动模拟许可。高影响、过期、来源错误、覆盖不足和跨窗口旧意图另用隔离场景核验；保护退出保留。
6. **自行跑模拟账户**：通过真实 HTTP 服务验证接收→后续报价成交→SL/TP→反向先平仓→停止；多空、重复报价、重启、版本冲突、事务失败均有反例。线上以自建验收账户核对真实行情与门禁，不停止用户旧账户。新闻缺失时不得为了展示成交绕过门禁。
7. **交付与发布**：测试站展示固定真实研究摘要、所有成本假设与下载入口；手机可读、表单和弹窗可操作。最终提交通过项目完整 CI，服务器源码与账本保留可核对。原始 tick、私钥和服务器配置不提交到前端。

完成不等于盈利或允许实盘。亏损、新闻未覆盖、数据缺口和黄金来源差异必须随结果一起展示；这些条件不满足时，线上开仓门禁继续拒绝。
