# Complete financial and local worker evidence archive

`paper-segmented-local-operational-archive-v1` has scope `FINANCIAL_AND_LOCAL_WORKER_FENCES`. It exports all immutable financial commits and the declared worker enrollment, lease/takeover claims and financial admission receipts from one account lock/transaction. Explicit worker enrollment is required; an unbound ledger can use the separate financial-only archive. No schema change is needed beyond0028.

Capture with `.venv/bin/python -m scripts.capture_segmented_ledger --ledger-id segmented:YOUR_ID --output /protected/new-file.json --operational`. The protected output is new-only mode0600, rejects symlink targets and fsyncs file content. Capturing does not add a financial commit or worker record. Concurrent writes serialize on the existing account lock, so the financial head and worker evidence come from the same checkpoint. The2-second lock timeout remains in force.

Verify with `.venv/bin/python -m scripts.verify_segmented_ledger /protected/new-file.json`. The CLI recognizes the exact financial-only or complete operational version and enforces that scope's input size. No database settings or connection are required for verification; tests run with an invalid DATABASE_URL. Duplicate JSON keys, nonfinite constants and unsupported/malformed contracts fail with a bounded generic result rather than printing artifact data or credentials.

Offline operational verification first reconstructs every financial command and account settlement using the existing financial archive contract, then applies the same worker-chain replay used by PostgreSQL auditing. It requires the declared enrollment/version, exact ledger identity, contiguous worker record hashes/sequences, root/head endpoints, unique worker command IDs and monotonically advancing financial admissions. Claims must bind the current financial checkpoint, increase tokens exactly, wait for predecessor expiry and preserve explicit duration. Every non-root financial commit must have exactly one admission carrying its original command ID, node hash, owner and token inside the current lease. Missing enrollment/claims/admissions, mixed checkpoints, stale/expired admissions, premature takeover and resealed settlement changes fail. Declared worker coverage cannot be stripped into an unbound archive of the same version.

The financial contract keeps its64MiB retained-JSON and512-commit limits; worker evidence keeps576 records of at most16KiB each. The outer operational JSON limit is the existing financial envelope limit plus576*16KiB and16KiB envelope overhead. Limits are simultaneous and no financial or worker capacity increases. Operational verification also checks every per-record bound. The financial-only version retains its own input limit and meaning.

This proves internal consistency of the supplied complete transcript. Hashes and caller owner strings do not authenticate provenance, grant current access or prove that this is the latest database state. An attacker can present an earlier complete consistent checkpoint without an externally trusted expected head; verification does not establish freshness. Exported lease timestamps are historical, not a current worker grant. Reports retain operator_worker_binding_supported=false and external_submission_allowed=false. Neither archive version authorizes replay/import to live state, retention deletion, external trading or unattended scheduler work. Financial-only archives never become worker evidence merely because the capture audited worker records in the database.

Tests use simulated fixtures and isolated PostgreSQL databases. Populated custom backup/restore compares the entire operational archive and all database table-content hashes. This does not demonstrate infrastructure failover or independent offsite durability. Authenticated operator/source/control/health/pool gates and application-worker scheduling remain unfinished, and their evidence must use an explicit future scope when implemented.

Existing frozen installation/start instructions and service readiness probes remain applicable. These source-only tools require no new service, dependency, frontend build, credential or allowed domain. Preserve the existing main configuration/history and never seed production ledgers to demonstrate this archive.
