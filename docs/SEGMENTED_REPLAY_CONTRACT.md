# Segmented request replay prerequisite

`core/paper/requested_segmented_execution.py` defines `paper-requested-segmented-replay-v1`, separate from frozen execution and journal-v1/v2 exports. This is a single-request, bounded, deterministic offline contract. It does not write a database journal, migrate an existing account, admit a command, authorize a worker or delete retained evidence. `ledger_application_supported=false` and external execution remains disabled.

The immutable request uses existing explicit-quantity request identity, protective price/fee/grid rules and opening economics. Existing settlement arithmetic is shared through a private capacity-parameterized reducer; the public frozen reducer retains its1000-event grammar. Settlement checkpoint fields retain the settlement-rules version, while the enclosing transcript declares the new segmented version and fixed capacities. A segmented artifact cannot be verified as a frozen execution export.

Segments contain1..128 ordered source events, at most128KiB including their checkpoint. At most256 segments,8192 total events and32MiB aggregate encoded evidence are accepted. Each segment binds its ordinal, contiguous global sequence range, predecessor digest and complete replayed financial/settlement checkpoint. The first predecessor binds the immutable request and capacity header. Every checkpoint is recomputed from the full preceding event ledger, preserving deduplication, pending holds, fees, cost basis, realized PnL, UNKNOWN and cancellation semantics. Event identities are unique across segments; repeated identical fill identity has one economic effect, while conflicting fills fail. These global identities are scoped to this one request, not multiple accounts or requests.

`append(report,batch)` verifies the existing artifact first, appends one bounded contiguous segment and confirms earlier segments are unchanged. Exact retry of the final batch returns unchanged evidence even after a seal. Other old-batch retry recognition, persisted server receipts, current worker fences, STOP/risk/health admission, atomic account revision changes and lost-reply recovery are not implemented by this function. New observations after a source seal require separate reconciliation and remain rejected.

Offline file verification: `.venv/bin/python -m scripts.verify_requested_segmented /protected/segmented.json`. Input is byte-bounded and duplicate-key/nonfinite JSON fails; no database/exchange access is needed. Internal hashes establish consistency, not source authenticity or completeness against an independently trusted manifest. A newly resealed valid prefix is still a valid prefix; trusted durable manifest identity/reachability is required before mutation or retention.

Validated examples include1003 events ending in full settlement, the8192-event capacity boundary with holds retained, cross-segment duplicate/conflicting fills, UNKNOWN/cancel/late-fill behavior, immutable append/retry, sequence/count/byte refusals and resealed incorrect checkpoints. Existing frozen execution, inspection and isolated journal/pool/drain/recovery regressions remain required.

Prove account/request exhaustion, rollback, SIGKILL/lost replies, takeover and restore before enabling a scheduler. Do not retrofit overflow into frozen audit paths by changing constants.

The protected local evidence substrate is now implemented separately; see [SEGMENTED_STORE.md](SEGMENTED_STORE.md). Its immutable snapshot chain and atomic index pass real process-crash/retry tests, while financial and worker authorization integration remain explicitly unsupported.
