# Paper 执行前准备契约

本阶段把闭合 K 线的准备与账本接受分为两个数据库事务。第一阶段独立提交 `PREPARED`，第二阶段在重新核对账户、行情和时限后提交账本及模拟订单终态。它提供可检查的持久准备事实，不提交交易所订单，也不承诺外部系统的 exactly-once。

## 不可变准备输入

准备有效载荷采用 `paper-closed-bar-preparation-v1`，精确包含 `version`、`session_id`、`base`、`observations`。`base` 保存账户 revision、status、halt_at，以及 snapshot_sha256、ledger_sha256、observations_sha256；它冻结原账户事实的摘要，不复制完整快照或原账本。`observations` 保存最多 10 根已闭合且从下一预期时间开始连续的 K 线、各自带时区的 observed_at 和原门控。payload_sha256 重算整个有效载荷；preparation_id 重算版本与有效载荷，完整输入相同便产生相同身份。消费须先验证当前账户账本可复算，再比对全部 base 字段，不能只认定保存的哈希正确。

记录 created_at 和 finished_at 使用实际 UTC 数据库操作时刻；它们不伪装为用于确定策略门控的历史 observed_at。准备及消费显式观测时刻须带时区且不得来自未来；准备观测不得早于所选 K 线收盘。载荷精确结构、base字段与类型、连续行情与统一观察时刻均受校验；创建/结束时刻必须带时区且结束不得早于创建。冻结的 observed_at 决定原有 `PRE_ACTIVATION`、`PAUSED`、`STALE_BAR`、`ELIGIBLE` 门控；既有闭合收盘价 Paper 公式、策略参数、风险参数和稳定模拟 order_id 规则不变。准备输入不能把策略的待执行 target 解释为已确定数量的订单。

同一账户最多保留一条 `PREPARED`，数据库部分唯一索引与账户行锁共同约束。每个账户最多保留 1,000 条准备记录；达到容量必须拒绝新增，不删除旧记录来假装成功。最终状态仅允许从 `PREPARED` 进入 `CONSUMED` 或 `CANCELLED`，不可再次进入待执行状态。有效载荷与摘要在终态转换中保持原样，终态另记录完成时刻与取消原因。迁移 `0011` 的触发器拒绝删除、修改不可变字段或再次更新终态。

## 两阶段提交与锁顺序

第一阶段先锁账户，再核验持久账本、独立模拟订单终态和当前行情规则及已接受行情前缀，选择闭合且连续的下一批 K 线。提交前以临时候选对象重算追加后的账本，验证候选数据和旧公式；此纯计算不持久化候选经济效果。实际保存批次时独立提交准备记录，不提前修改账户 observations、账本或 revision，也不生成该批次的模拟成交。

没有可保存批次时，准备路径仍沿用既有轮询语义：更新 WAITING、GAP 或 STALE feed；规则或已接受行情变化会 BLOCKED 并增加 revision；达到原有行情容量会进入 LIMIT_REACHED。兼容的历史独立终态补齐也可能发生。不能把整个 prepare 方法宣传为永远无账户写入；无新增批次经济效果与完全只读是不同保证。

第二阶段始终先锁账户，再锁准备记录，与账户控制及其他 worker 使用同一顺序。消费已有终态记录不得重做经济效果；消费 `PREPARED` 须重新检查：

- 当前账户 ID、revision、status、halt_at 及快照、observations、账本的摘要全部与冻结 base 一致。
- 当前 Instrument 规则、完整已接受行情前缀以及全部准备行情仍与冻结输入一致；缺失、修订和未闭合都不能执行。消费查询严格限制冻结批次的数量，批次之后后来补齐的行情不能扩大本次接受范围，也不被误判为冻结行情修订。
- 原账本仍可按冻结版本重算，既有独立模拟订单终态仍与原账本匹配。
- 消费时刻合法，且所有原本 `ELIGIBLE` 的 K 线仍在 max_lag_seconds 时限内。延迟恢复不能利用较早 observed_at 获得过期的执行许可。

条件通过后，在同一事务内追加冻结 observations、重算既有公式的账本、持久化对应模拟订单终态、更新账户 revision 与 feed，并标记准备记录 `CONSUMED`。任何中途异常都回滚这一组写入，准备记录仍可供后续检查。

控制、时限或行情条件不满足时，将准备标记 `CANCELLED` 并记录 `CONTROL_CHANGED`、`EXPIRED` 或 `SOURCE_CHANGED`；完整性异常直接失败并回滚，不伪造正常取消。不能悄悄替换输入后复用旧身份。账户 pause、resume、halt、stop 产生实际控制变化时，在同一控制事务中将待消费准备取消，保持原控制审计与账户版本规则；消费也会复核 base，旧准备不得覆盖新控制状态。行情变化沿用既有拒绝与 BLOCKED 语义，不能回填或修补已成交账本。新的准备必须重新核对当前事实。

## 中断、重试与恢复验收

| 中断位置 | 持久事实 | 重试要求 |
| --- | --- | --- |
| 准备事务提交前 | 无新增准备、无新增经济效果 | 可重新准备 |
| 准备已提交但响应丢失 | 唯一 PREPARED 已存在，账户未接受新行情 | 找回原记录，不创建第二条待执行记录 |
| 准备提交后、消费开始前 | 账户原账本与冻结准备同时存在 | 重新核对控制、行情和时限 |
| 消费事务写入后、提交前 | 整个消费事务回滚 | 无半条账本或模拟订单终态；准备保持待核对 |
| 消费提交后、响应丢失 | 账户、独立终态和 CONSUMED 同时存在 | 返回持久结果，不再次追加 observations 或成交 |
| 消费前控制变化、行情修订或过期 | 原准备不再有执行资格 | 明确取消，不自动重放 |

故障测试应分别覆盖两个提交边界、重建连接后的找回、并发准备与并发消费、锁顺序、容量拒绝、控制变化、数据修订和过期。断开连接重建不等同于已验证整个进程或基础设施重启；报告必须按实际故障范围陈述。

## 兼容性与对外边界

原独立模拟订单终态导出版本、离线核验公式和历史账户兼容路径保持不变。准备记录是执行前闭合 K 线批次，不是交易所 ACK，不是已成交数量，也不是独立 OMS 的完整状态机。Live 仍关闭；本阶段不增加真实交易所凭据或订单入口。

只读 GET `/api/v1/paper/streams/{id}/preparations` 及实时Paper页显示清晰区分 `PREPARED`、`CONSUMED`、`CANCELLED` 与策略 pending target。只读检查不消费准备，不改变账户，不启动恢复或交易。该准备列表校验结构与载荷摘要，有最多1000条和32 MiB响应限制；没有完整旧账本输入，不提供独立离线账本复算或下载。完整原账本/已完成意图的既有下载与离线核验继续有效。准备摘要不证明外部来源真实性。
