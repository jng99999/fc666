# 持久化 Paper 订单意图契约

本切片只覆盖实时闭合柱模拟账户。独立持久行保存已经完成的模拟订单意图及其完整转换序列，用于核对已持久执行事实，不连接交易所，不开放提交、取消、恢复或重放命令。`LIVE_TRADING=false`。现有 `spot-paper-closed-close-v1` 公式、订单 ID、历史导出和人工控制契约保持有效；完整实盘 OMS 仍按 [EXECUTION.md](EXECUTION.md) 单独实现。

## 身份与不可变事实

策略的 `AWAIT_NEXT_CLOSED_BAR` 是尚未执行的目标，不预先生成订单意图。只有原引擎为后续已接受闭合柱生成实际订单记录时，才保存对应意图。预热柱、暂停、迟到和预激活门禁仍按原引擎处理；原引擎产生的拒绝记录同样需要保存，不能忽略失败事实。

意图 ID 使用版本化、确定性的摘要，包含意图契约版本、账户 UUID 和原模拟 `order_id`；原引擎版本保存在不可变载荷中。账户 UUID 是必需的命名空间：两个账户可能拥有相同冻结输入及原订单 ID，但必须形成不同意图。原订单 ID 原样保存，不能因增加持久化结构而改写旧成交关系。唯一约束覆盖账户与原订单 ID及全局意图 ID；行内转换数组由完整路径验证，不能出现重复或缺口。

不可变载荷包含契约版本、账户身份、冻结快照摘要、引擎版本、完整原订单，以及对应完整模拟成交或明确的 `null`。保留原字符串金额、决策时间、执行柱时间、观察时间和 `simulated=true`。成交中的费用、参考收盘价、成交后现金与库存均属于原事实，不重新格式化或用当前行情替换。重复写入同一身份时须逐项核对完整载荷；不同载荷不能通过忽略唯一冲突被静默接受。

原账本与独立记录之间必须完整对应：每个原订单恰有一个意图，每个原成交关联同一订单，拒绝订单无成交，成交数量等字段与原订单一致。多余、遗漏、错误账户、错误摘要或损坏转换记录均拒绝核验。

## 模拟状态机

转换只描述同一次本地模拟的计算结果，不声称发生外部提交或交易所确认。

| 原账本结果 | 保存的转换序列 | 终态含义 |
| --- | --- | --- |
| `FILLED` | `CREATED -> VALIDATED -> FILLED` | 原引擎要求的量已在模拟中成交 |
| `PARTIAL_CANCELLED` | `CREATED -> VALIDATED -> PARTIAL_CANCELLED` | 原引擎因容量限制只成交部分，其余量在本次模拟中结束 |
| `REJECTED` | `CREATED -> REJECTED` | 原引擎按原始门禁、规则或风险原因拒绝；无成交 |

现有引擎确实产生 `PARTIAL_CANCELLED`，不能将它统一改名为 `FILLED`，也不能虚构 `CANCEL_PENDING`、外部取消确认或后续余量成交。拒绝原因原样保存。`transitions` 是完整状态字符串数组，例如 `["CREATED", "VALIDATED", "FILLED"]`；顺序由数组下标确定，没有独立转换对象、转换时间或显式序号字段。核验将整个数组与原订单终态对应的唯一合法路径精确比较，禁止跳过验证、重复终态或终态回退。

这些状态在同一事务中完整落盘，不是异步交易队列。`VALIDATED` 证明原模拟规则已允许该次成交，不能成为未来私有 API 请求的授权。执行时间沿用历史柱与观察时间；实际保存时间单独记录，不把旧执行时间当作数据库刚提交的时间。

## 原子提交与幂等

原有账户行锁串行化同一账户的消费与人工控制。接受观察、重算账本、更新资金和账户版本，以及新增意图和全部转换，必须使用同一个 PostgreSQL 事务。提交前任何失败全部回滚；提交成功但响应丢失后，重读或重复扫描返回同一身份与同一经济事实。

事务开始先核对已有账本及独立记录，再保存新增订单。已存在的载荷或转换发生冲突必须失败，不能用当前重算结果覆盖。禁止修改或删除已保存意图及转换；数据库约束或触发器应阻止绕过应用的覆盖。账户行锁之外的唯一约束仍是防重复防线。

独立记录只是原模拟账本的可核对持久事实，不能单独修改余额。人工 `pause/resume/halt/stop` 继续使用既有账户版本与控制审计；人工控制请求 ID、模拟订单 ID、意图 ID 互不代替。

## 已有账户的显式物化

部署前的历史账户可能有完整账本但没有独立意图。不能将这个情况解释为旧成交未发生，也不能在 GET、恢复检查或浏览器打开时暗中补写。

账户新增可空 `intent_version` 标记。新账户从创建起使用新契约版本；旧账户的 `NULL` 明确表示 `LEGACY_UNMATERIALIZED`。旧账户下一次已有且获授权的人工控制或 worker 消费，在账户行锁内先重新核验冻结输入及原账本，再物化已有订单，随后按原契约处理本次控制或消费。历史记录来源标记 `HISTORICAL_MATERIALIZATION`，后续新增订单标记 `BAR_ACCEPTANCE`。记录实际保存时间，不能将 CREATED 或 VALIDATED 伪装成过去数据库中已经独立发生的事件。

物化步骤自身不接受新柱、不补成交、不改变原账本、资金、账户生命周期、账户版本或人工控制记录；外围原控制或消费可以产生其本来允许的变更。重复物化核对既有完整记录后保持幂等。终止账户在没有后续写入前可一直保持未物化，GET 不为其自动执行维护。

未物化账户明确返回 `LEGACY_UNMATERIALIZED`；不能返回空列表并宣称它证明没有历史订单。已有版本标记下的部分缺失或冲突记录属于损坏，不能当作首次物化自动修复。没有真实订单的已物化有效账户可以得到零条记录的完整核验结论。

## 读取、离线验证与边界

`GET /api/v1/paper/streams/{UUID}/intents` 在 PostgreSQL `REPEATABLE READ` 事务中取得账户、意图及转换，重新执行原版本引擎后完整比较所有记录。只读接口不修复、迁移或改变账户。契约版本为 `paper-completed-order-intent-v1`；完整已物化账户返回 `coverage=VERIFIED`，旧账户返回 `LEGACY_UNMATERIALIZED`。返回始终包含 `trading_enabled=false`、`automatic_replay=false` 和 `in_flight_submission_supported=false`。

导出保存完整 `inputs`，包括 `version`、服务器 `as_of`、冻结账户 `record` 及全部独立行 `stored`；结果还带完整记录及输入摘要。账户输入保留冻结快照、观察、原账本、版本、生命周期、halt、feed 和物化版本。离线工具重算原账本、载荷摘要、确定性身份、完整覆盖及路径，再比较完整导出结果，不依赖当前数据库、行情或交易所。未知版本、非法状态路径、额外或缺失记录、未来保存证据、摘要或重算不一致应拒绝。来源标记仅验证允许的枚举值，不能仅凭一份离线文件独立证明历史物化实际发生的时刻或原始写入过程。

文件上限为 32 MiB。核验命令为：

```bash
.venv/bin/python -m scripts.verify_paper_intents /path/to/paper-intents.json
```

摘要只证明文件内部一致性，不证明操作者身份或外部真实性。现有恢复检查仍保留其版本及导出契约；新增意图检查应独立版本化，避免要求旧导出携带部署时尚不存在的记录。

验收应覆盖 FILLED、PARTIAL_CANCELLED 与 REJECTED 的准确路径、不同账户身份隔离、重复物化、损坏或部分缺失拒绝、数据库不可变约束、提交前回滚、提交后丢确认、连接重建和并发重复扫描。已有账户物化前后原账本与控制记录须逐项相同。浏览器核验与下载失败时清除旧确认，不能提供修改意图或重新执行按钮。

这些验收只证明本地 Paper 事务与可重复读取。CREATED 与 VALIDATED 不曾独立于终态提交；在执行前单独持久化并恢复待执行意图仍未实现。外部 exactly-once、真实订单请求幂等键、UNKNOWN_SUBMISSION、交易所回执、私有成交对账、共享资金及实盘恢复均未实现。
