# 黄金历史研究设计（2026-10-21）

沿用独立黄金服务和现有八个版本化策略，不改旧加密模型或模拟账本。用户明确授权补齐回测、发现问题直接修复并更新测试站，因此设计与实现按现有范围推进。

选择HistData官方Generic ASCII月度tick公开下载，逐笔bid/ask原样归档校验SHA256。旧Dukascopy下载接口429，新接口出现WAF challenge，停止使用，不绕过。HistData官方文档说明固定EST、不调夏令时、tick含bid/ask，bar格式只有bid，因此不能用其M1数据伪造历史点差。

按固定UTC窗口构建1h，首尾报价距离边界至多120秒、内部采样缺口至多300秒；4h仅聚合四根完整1h。保留真实空缺，不填平假柱；缺口包括休市和未知缺失，不在没有交易日历证据时声称全部是休市。指标按已观测闭合柱序列计算，下一周期无首报价或首报价过晚时取消旧意图。每笔成交使用下一UTC周期首条真实bid/ask，报价独立于该周期后续K线完整性；决策时刻不得晚于报价时刻。0.01盎司步长、10盎司单笔上限和仅做多/空仓沿用黄金研究约束。

复用八个固定参数策略，独立美元资金；同时对比无成本参考、原始点差加设置费用/滑点、两倍点差加两倍费用/滑点的压力情况。手续费与单边不利滑点为用户明确的研究假设，原始点差来自真实tick，不等于瑞讯或用户经纪商费率。闭合柱指标只用当时已知数据；末尾未执行信号不补单，开放持仓按适用bid估值，不做虚构强平。记录成本、权益、回撤、已闭合交易胜率、未实现盈亏和数据/参数/引擎摘要。

预先按时间划分完整年份发展区、验证区、最终年份保留区；对每个区间独立资金、历史预热，保留区不按结果挑选参数。展示完整矩阵及每年结果，而不只展示冠军。更长历史和正收益都不自动证明未来盈利。融资、隔夜掉期、真实深度与实际滑点仍未重建。

后端采用独立研究任务表和单个后台线程，POST仅入队，GET无推进交易的副作用。每笔请求UUID+参数摘要保证重试一致，按黄金会话隔离，限流限制计算规模，重启纯研究计算可重新排队，结果持久化。数据只读快照与任务结果独立于实时账户事件，原账户、旧账本保留。

UI在黄金入口增加历史研究链接，提供数据质量、策略/周期多选、成本输入、进度/失败重试、排序对比、权益曲线、逐笔结果和JSON/CSV导出；沿用Apple控件和手机安全区，不加第七个底栏按钮。验证包含时序前缀稳定性、真实bid/ask及成本守恒、空缺/暖机/末尾信号、并发重试、跨会话权限、重启、导出及手机溢出。CI与线上验收完成后才报告通过，实盘保持关闭。
