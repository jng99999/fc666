# Scoped local unsubmitted-finalization API

POST `/api/v1/paper-requested/finalization-commands` uses the same default-disabled local operator authentication as control-commands, with a separate explicit server action grant `VOID_UNSUBMITTED`. Existing PAUSE/HALT/STOP/RESUME grants do not imply permission to release reservations; a void-only grant cannot run those control commands. Exact account membership is required before storage access. No token or account is installed in main by setup.

The exact body contains account_id (opaque string,1..128), request_id (64 lower-case hexadecimal characters), command_id (stable string,1..128), expected_financial_revision (strict JSON integer>=1), and created_at (aware ISO clock). Extra fields, numeric strings and boolean revisions fail422. Bearer authentication is header-only. Disabled503, invalid/missing credentials401 and account/action denial403 happen before storage access; authorized missing account404, incompatible/unverified histories or conflicts409, database/lock errors503. Handled responses use no-store; standard422 remains FastAPI behavior. Scoped enrollment and read-only previews are now available separately; see PAPER_REQUESTED_ONBOARDING.md. Separately granted preparation is now available; see PAPER_REQUESTED_PREPARATION_API.md. No SUBMIT, source-event ingestion or Live API is added.

Inside the PostgreSQL account lock, the operation verifies the complete financial/control history and requires explicit CONTROLLED enrollment. Legacy unmanaged accounts remain accessible only through their prior internal operation. The current active request must have zero durable source events and the supplied financial revision must match. These predicates and immutable void insertion/reservation release share one transaction. First SUBMIT and void cannot both win. A submitted request, including unknown submission outcome, retains its hold. The two-second lock_timeout bounds database lock waiting, not overall request time. No separate control revision is required: closure is permitted in every existing controlled state, does not change that state, and checks the latest control clock under the same lock. It grants neither resume nor new-work permission.

The response version is paper-requested-finalization-command-result-v1. Its request_id, command_id and finalized_request_summary acknowledge the original local closure, with external_submission_allowed=false. Exact retries return the same acknowledgement even after another request has been prepared; this historical summary is not the current account's available balance. A conflicting identity/clock/revision cannot release a later request. Current authentication and grants are checked for every retry. The immutable proof is available through the existing GET journal and financial/control v2 exports, all with their existing offline verification. No schema or export-format change is required.

This remains single-operator local capability access, not multiuser identity, a per-person audit log or proof of venue absence. It never invents source events or exchange cancellation. Follow the existing secure-token/transport instructions in PAPER_REQUESTED_COMMANDS.md. Main remains default-disabled, five services ready and Live off; fixture accounts and artificial credentials exist only in isolated tests. Scoped enrollment and funding preview are implemented; see PAPER_REQUESTED_ONBOARDING.md. Atomic preparation is implemented; see PAPER_REQUESTED_PREPARATION_API.md.
