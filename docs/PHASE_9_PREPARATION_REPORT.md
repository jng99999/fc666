# 执行前准备与恢复消费验收

后台闭合柱 Paper 消费现在先独立提交 PREPARED，随后在第二个事务核对账户 base、当前 Instrument、已接受与准备行情、及时柱的允许延迟。准备期间尚无该批次经济效果；消费成功时观察、账本、独立完成态订单和 CONSUMED 同时提交。准备的是闭合柱批次，不是确定数量的交易所订单。

账户控制的实际变化同事务取消旧准备；恢复后过期及时柱取消而非沿用旧 observed_at 成交，后续重新扫描按迟到规则处理。行情或规则变化取消并阻断账户。数据库保护载荷、合法终态转换及时间顺序；唯一待消费索引、账户先锁与容量1000条拒绝保证不重复新增经济事实。GET及页面不触发消费或维护，列表最多32 MiB。

首轮回归识别消费结束时间过早赋值导致自动flush试图写入中间不完整状态，已将状态/原因/结束时间放在经济计算之后一起提交。独立审阅同时补强精确base类型、连续观察、统一时刻、非未来显式时间以及保存/结束时钟验证。

原接受事务故障测试现按账户经济版本变化定位到消费阶段，仍断言SQL已flush后整笔回滚，而不是错误地只验证准备提交失败。新增准备/消费两种提交失败分别验证；新连接找回准备与同一准备幂等消费、双worker、控制变化、过期后迟到拒绝、旧前缀/新准备柱/Instrument修正、不变触发器、容量和只读API均覆盖。测试只写隔离PostgreSQL，不制造产品市场数据。

全套340项测试通过（158.83秒，1项既有FastAPI/httpx弃用警告），Alembic无新操作，TypeScript与生产构建通过。其后限制消费查询为冻结批次的数量，防止后来补齐的缺口扩张旧批次或误阻断账户；追加针对性回归后，当前23项准备专项全部通过（7.24秒）。该新增回归保留数据库Decimal字符串精度，逐项比较实际冻结观察，而非比较测试构造时不同格式的数字字符串。五服务恢复后浏览器通过：真实旧停止账户准备列表读取、失败清除旧确认、轮询无重复组件、393px无溢出/JS错误、原账本未变、原恢复/独立意图下载离线核验通过。真实旧账户无准备记录，未为演示生成假行情或补造记录；非空PREPARED/CONSUMED/CANCELLED的数据库与API路径由隔离测试验证。本切片迁移0011，无新依赖、网络主机、秘密或服务；五服务启动入口仍为 scripts/start.sh。无进程级kill/restart注入，连接重建仅按实际范围报告。下一目标是每订单明确的执行前授权和执行门禁；完整OMS、真实提交/ACK/私有对账、共享资金、鉴权与Live仍未实现。
